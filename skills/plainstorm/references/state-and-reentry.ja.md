# 状態、試作、再開

## 何を示し、何を保持するか

通常の応答では、新しく出たもの、重要な変化があったもの、または再び開いたF/U/Dだけを示します。空の表は省略します。現在扱っている未解決事項(U)が解決したら、その解決への移行を1回だけ示し、その後はUから外して、結果をFまたはDに取り込みます。全体のまとめを示すのは、実際の計画や、方針・約束、引き継ぎを確定する区切りに達したとき、またはユーザーが明示的に求めたときだけです。

状態の保存は任意です。複数回のやり取りをまたいで再開するのに役立ち、書き込み権限もある場合に利用できます。タスクの状態や、会話・引き継ぎの短い再開メモがあれば、それを起点にします。新しい作業に固定の保存先は必要ありません。状態ファイルを使う場合は、作業中に同じ簡潔なファイルを使い続けます。既存の作業がすでに `~/.codex/state/brainstorming` を使っている場合に限り、その保存先を引き続き使えます。一括移行は行いません。保存できない場合は、現在の要点、重要なF/U/Dの差分、選んだ進め方、残る未解決事項、次の検証を短くまとめ、会話や引き継ぎに残します。会話をそのまま写した記録、秘密情報、認証情報、無関係な非公開データは保存しないでください。

## 試作の境界

試作を作る前には、ユーザーによる明示的な選択が必要です。ユーザーが範囲を区切った試作を明示的に選び、その範囲をすでに許可しているなら、そのターンで進めてください。承認をもう一度求めてはいけません。選ばれた試作に成果物の種類と個数が指定されているなら、タスクの作業用の一時フォルダーに、指定された種類と個数だけを作り、追加の成果物は作りません。試作は、ローカルで、範囲が区切られ、元に戻せて、観察を中心にし、破棄できるものでなければなりません。観察内容と停止条件も明確にします。外部への送信やフォーム入力、認証や秘密、金銭、公開やデプロイ、破壊的または元に戻せない作用に使ってはいけません。重要な観察結果をループに戻します。作ったこと自体を承認や完了とみなしてはいけません。

## 証拠に基づく再開

再開時は、予想と実際の観察結果を比べ、重要なF/U/Dの差分だけを記録して、次の進め方を選びます。観察結果が変われば、解決済みの項目を再検討したり、新しい具体的なUを追加したりできます。解決した項目は重複するUとして残さず、FまたはDに取り込みます。実装メモのファイルを必須にしたり、作業の開始から終了までを管理する仕組みを追加したりしないでください。続きに必要な最小限の再開メモを残し、証拠や権限が足りない場合は、未完了の範囲を明示して止めます。

このスキルには、クイズ、必須の解説成果物、必須の `.agent/unknowns` ファイル、Pythonハーネス、テレメトリー、証拠グラフ、ゲート、キュー、モデル起動器は含まれません。かつての「およそ3問」という経験則は置き換えられており、規則として登場してはいけません。
