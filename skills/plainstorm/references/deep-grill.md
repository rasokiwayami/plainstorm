# Deep Grill

Enter Deep Grill for a material blocker, not because a certain number of
questions has been asked. A request for exhaustive grilling, material
branching, high impact, or hard-to-reverse consequences is sufficient. Keep a
material design tree: each node records the decision it can change, its
dependencies, and the evidence or user judgment needed to resolve it.

There is no numerical question cap or target. At each round:

1. Recompute the tree and identify the complete currently independent
   frontier.
2. Ask that frontier in one numbered round. Include a recommendation and
   consequence for each question, covering each meaningful answer.
3. Defer dependent questions until their prerequisite is answered, then
   recompute the tree after answers. Split oversized scope into separately
   bounded decisions instead of truncating the frontier.

Research discoverable facts. Ask the user for preferences, authority, private
context, or trade-offs that only the user can decide. A reference, reaction,
option, or prototype can supply evidence, but it does not silently decide a
user-owned branch.

Research and prototype are route transitions, not completion states: each
returns with evidence and the loop updates its tree. Deep Grill is not complete
merely because a blocker was assigned to research, prototype, assumption, or
defer. A material branch may be deferred only when it is outside the current
scope or the user accepts the consequence. An assumption must name its
consequence if false; completion requires no material assumption to remain
silent.

Treat user pushback, scope narrowing, and "I don't know" as useful branch
evidence without coercing an answer. Route unresolved information to
research/prototype or keep it active; the branch remains visible until its
material consequence is resolved or explicitly bounded.

Completion requires every material branch to be visited. After that visit,
every remaining material item is resolved or explicitly bounded, with user
confirmation of shared understanding of the selected direction, assumptions,
and next validation. The user may stop earlier; report the incomplete boundary
honestly, including remaining material branches. Never imply that unknown
unknowns were eliminated.
