# PlainStorm

PlainStormは、まだ形の決まっていない案や判断について、状況に応じて進め方を変える対話スキルです。目的、制約、成功条件、次に確かめることを整理し、短い整理、深掘り、調査、選択肢や試作の比較、結果からの見直しを使い分けます。デバッグ、コードレビュー、仕様がすでに確定した通常の実装作業は対象外です。

## できること

ユーザーが決めること、事実の調査、試作から得られる観察を混同せずに、曖昧な判断を範囲を区切った次の検証へ変えていきます。

## 例1: 方針が決まっている場合

「対象者、チャネル、締め切り、成功指標は決めました。告知文の下書きを手伝ってください。」

PlainStormはLightルートを使い、質問枠を勝手に設けずに、依頼の範囲に絞った構成案を作れます。

## 例2: 言語化しにくい好み

「まだ視覚的なスタイルを説明できません。作り始める前に、手元で比較できる、はっきり異なる案を2つ見せてください。」

PlainStormは、Options/Prototypeによる比較を提案できます。ユーザーが範囲を区切った選択を明示した後は、その選択で定めた範囲で進め、観察結果をループに戻します。

## フォルダーのコピーと削除

この `plainstorm/` フォルダー全体を、対象のCodexインストールが使うスキルディレクトリにコピーしてください。不要になったら、コピーしたそのフォルダーだけを削除します。インストーラー、ランタイム、プラグインマーケットプレイス、専用のリポジトリ構成は必要ありません。

## 任意の状態

状態は任意です。利用できるタスク状態ファイルがあれば、複数ターンにまたがる再開を支えられます。なければ、対話または簡潔な引き継ぎカプセルで十分です。すでに実行中の作業が従来の状態保存場所を使っている場合は、その場所を引き続き使えます。新しい実行に固定のホームパスや状態の移行は必要ありません。

## 証拠の限界

構成の検査や、架空の場面を使ったエージェントの試行だけで確認できることには限りがあります。このフォルダーには、検査用のテスト一式や試行用プログラムは含まれていません。これらの試行は実際の利用者による評価ではなく、どのような依頼でもPlainStormが適切に自動選択されることまで確認したものではありません。利用状況を収集する仕組みも追加しません。外部への操作はPlainStormの権限に含まれません。試作はローカルで、範囲を区切り、元に戻せて、必要なら破棄できるものに保ってください。
