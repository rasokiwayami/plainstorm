# PlainStormの使い方

PlainStormを読み込めるCodexで、相談の最初に「PlainStormを使って」と添えます。考えがまとまる前から使えます。

## 最初の依頼

> PlainStormを使って、○○の案を整理したいです。目的は△△で、□□がまだ決まっていません。

分かる部分だけ書けば十分です。すでに決めたこと、参考にしたいもの、避けたいことがあれば、一緒に伝えます。

## 場面に合わせた頼み方

| したいこと | 依頼例 |
| --- | --- |
| まず短く整理する | 「この案について、重要な未決定事項と次に確かめることを整理して」 |
| 深く検討する | 「反対意見や代替案も含めて、判断を変え得る分岐を掘り下げて」 |
| 分からない事実を調べる | 「調べられることは調べて、確認できた事実と、私が決めることを分けて」 |
| 言葉にしにくい好みを探る | 「見た目の好みをうまく説明できないので、違いが分かる方向性を提案して」 |
| 試した結果から考え直す | 「試してみたら、予想と違って○○でした。この結果を踏まえて見直して」 |

試作へ進むときは、どの案を、何として、いくつ作るかを伝えます。例えば「提案したA案とB案を、それぞれ静的な画面1枚としてローカルに作って。比較したいのは情報の見つけやすさです」と指定できます。

## やり取りの途中で伝えてよいこと

- **まだ分からない**：「そこはまだ決められない。判断材料を調べるか、小さく試す方法を考えて」
- **話を絞りたい**：「今は対象ユーザーを決めることだけに絞りたい」
- **重要な前提が違う**：「○○という前提は違います。正しくは△△です」
- **参考にする部分を限定したい**：「この参考例では、画面の配置を参考にしたい。目的や機能は私の案に合わせて」
- **途中で止めたい**：「ここで止めて、決まったこと・未決定のこと・次の一手を短く残して」

好みを説明しきれなくても、「こっちが近い」「ここは違う」という反応を判断材料にできます。

## 終わり方と再開

相談の区切りでは、決まった方向、残る不確実性、次に確かめる一手を確認します。実装へ進めるなら、その対象と範囲を選びます。

別の会話で続けるときは、残した短いまとめを渡し、「この続きから。前回から変わった点は○○です」と伝えます。前提が変わった部分から見直せます。状態ファイルを使える環境でも保存は任意で、新しい実行に固定の保存先や移行は必要ありません。

エラーの修正、コードレビュー、すでに決まった仕様の実装は、通常の作業依頼として進めます。
